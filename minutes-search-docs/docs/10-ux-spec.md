# 10 · UX spec

Calm, editorial, trustworthy. The app opens on what changed in your patch; every AI sentence is one click
from the passage it came from.

## 1. Principles

1. **Briefing first.** Signed-in users land on what is new for their councils and issues.
2. **Summary, then source.** Lead with the AI topline; every claim links to a highlighted passage.
3. **Label the AI.** "AI summary · check the source" on every generated block. Never present generated text as a quote.
4. **Honest about gaps.** Unreadable text, pending summaries and capped counts are labelled, with a next step.
5. **Plain language.** No API words ("unclassified", "DecisionOut"). Use the glossary in `01-product-spec.md`.
6. **Fast and quiet.** Skeletons not spinners; no modals except dialogs the user opened; no toasts for reads.
7. **Accessible.** WCAG 2.2 AA; everything works by keyboard; works at 320 px wide.

## 2. Design tokens

Define as CSS variables in `packages/ui/tokens.css` and map to Tailwind theme. Support light and dark.

| Token | Light | Dark | Use |
| --- | --- | --- | --- |
| `--bg` | `#FAFAF7` | `#121413` | Page |
| `--surface` | `#FFFFFF` | `#1B1E1D` | Cards, panels |
| `--ink` | `#16191A` | `#ECEDEA` | Body text |
| `--ink-muted` | `#5B6360` | `#A3AAA6` | Metadata |
| `--line` | `#E4E4DE` | `#2C302E` | Borders |
| `--accent` | `#0F6E6A` (deep teal) | `#4FB8B2` | Primary actions, links, focus |
| `--mark` | `#FFE8A3` | `#5A4A12` | Search highlights |
| `--signal-cut` | `#B42318` | `#F97066` | Cut/closure badge |
| `--signal-consult` | `#175CD3` | `#84ADFF` | Consultation |
| `--signal-money` | `#7A5AF8` | `#BDB4FE` | Contract/grant |

Badges always include text, never colour alone. Check contrast ≥ 4.5:1 for text.

Type: interface in a clean sans (e.g. Inter), document text in a readable serif (e.g. Source Serif 4),
self-hosted via `next/font`. Base 16 px; reader body 18 px / 1.6. Spacing scale 4 px. Radius 8 px.

## 3. Layout

- Top bar: logo, global search box (Cmd/Ctrl+K opens command palette), Saved, user menu.
- Left nav on desktop (Home, Search, Saved, Bookmarks, Councils, Admin for admins); bottom nav on mobile.
- Max content width 1200 px; reader text column max 72 characters.

## 4. Screens

### Home briefing `/`
- Greeting + date + "Your patch: Croydon, Sutton (edit)".
- **New for you**: per subscribed saved search, a card with name, "N new", top 3 items (topline, council,
  date, badges), "See all". Ordered by most new.
- **Coming up**: next 14 days of meetings in your councils whose agenda items match your topics, with the
  matched item heading and a "Remind me" (creates a follow-up saved search).
- **This week's digest**: AI overview of your week's matches (cached, generated by the weekly alert job).
- Empty states: no saved searches → "Set up your first alert" button to onboarding step 3; nothing new →
  "Nothing new since {time}. Last data update {time}."

### Search `/search`
- Query box with syntax help popover (`"exact phrase"`, `or`, `-exclude`).
- Filter rail (desktop) / filter sheet (mobile): Councils (search + chips), Area, Council type, Committee,
  Date (presets: 7 days, 30 days, 90 days, 12 months, All, Upcoming; custom range), Document type, Topic,
  Signal, Scope toggle (Full text / Summaries). Facet counts beside values.
- Results header: "1,284 results" (or "10,000+"), sort, "Save search", "Summarise these results", "Export".
- **Result card:** council · committee · date (relative + absolute on hover) · doc type badge · signal
  badges · topline (AI) · snippet with `<mark>` highlights · actions: Open, PDF, Bookmark.
  "3 more matches in this document" link. Upcoming meetings show "Coming up" badge.
- Digest drawer: right side sheet; streams text with `[R#]` citation chips that scroll to results.
- Empty results: suggestions (remove the most restrictive filter, widen dates, related topic, check spelling).

### Document reader `/documents/[id]`
- Header: title, council, committee, meeting date and status, doc type, "Open original PDF", Bookmark, Copy link.
- Left: agenda-item outline with match counts; current item highlighted on scroll.
- Centre: cleaned text by section; matches highlighted; next/previous match controls (keyboard `n`/`p`).
- Right (or top on mobile): **AI summary** panel: topline, key points, decisions, money, signals; each with
  numbered citation buttons → scroll to passage + highlight 2 s. "Report a problem" link.
- Related: other documents in the same meeting; "superseded by final minutes" banner when relevant.
- Unusable text: "Text not available for this document" + "Open original PDF" + reason.
- Deep link to a passage: `/documents/[id]#p-[passageId]`.

### Meeting `/meetings/[id]`
Brief (headline, items, decisions, status note), documents grouped by type, decisions, attendees if
present, link to the council's page for the meeting.

### Decision `/decisions/[id]`
Decision maker, date, outcome, key decision and call-in badges, brief, documents.

### Council `/councils/[slug]`
Name, type, region, majority party; upcoming meetings; recent decisions; committees; councillors by party
(counts + list); "Watch this council".

### Saved `/saved`
Tabs: Mine, Shared with my organisation. Rows: name, filters summary, frequency, new count, last alert,
actions (open, edit, share, pause, delete). Following/unfollowing for shared.

### Admin `/admin`
Access requests (approve to org / create org / decline), users, organisations, data health (from
`04-data-pipeline.md` §13), AI coverage and spend, dead letters with retry.

## 5. Copy rules

- UK English; sentence case for headings and buttons; no exclamation marks.
- Buttons are verbs: "Save search", "Summarise these results", "Email me a sign-in link".
- Errors say what happened and what to do: "We couldn't load results. Try again, or remove a filter."
- Dates: "Thu 20 Aug 2026"; times "7.15pm"; relative times under 7 days ("3 days ago").
- Numbers with separators: "1,284". Money as written in source in summaries.

## 6. Accessibility checklist

Landmarks and skip link; visible focus (2 px accent outline); all controls labelled; dialogs trap focus
and restore it; live region announces result counts and streaming digest completion; highlights not
colour-only (also underline); respects `prefers-reduced-motion`; axe clean in CI; manual check with
VoiceOver and NVDA on search, reader, onboarding.
